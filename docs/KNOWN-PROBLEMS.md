# Known problems and open risks

Role: Register of unresolved technical risks and validation gaps.
Read when: Planning technical research, encountering an uncertain boundary, or checking whether a limitation is established.
Authoritative for: Open risks and questions that do not yet have an accepted resolution.
Not authoritative for: Confirmed implementation bugs, current progress, accepted decisions, or roadmap order.

These are investigation items, not claims about code that does not yet exist.

| Risk | Why it matters | Intended resolution path |
| --- | --- | --- |
| Avalonia direct-Skia bridge is unstable API | The accepted initial photographic path uses public `ISkiaSharpApiLeaseFeature`, but Avalonia marks it unstable | Keep one replaceable adapter and validate upgrades before changing the package line |
| Runtime DPI evidence is single-display Windows at 100% | Pure math covers 100/125/150/200%, but simulated scale is not per-monitor or cross-platform runtime proof | Exercise real fractional/per-monitor Windows, Linux scaling, and Retina in a bounded follow-up |
| Windows SDR Monitor Color Management lacks broad hardware evidence | R8-B-W1 locally resolves one real Windows SDR display and proves app-local matrix/LUT transforms, but real two-monitor transitions, fractional-DPI hardware, unusual vendor LUT profiles, and low-end interaction feel remain narrower than the pure/synthetic evidence | Require normal and native hosted matrices after owner push, then collect real multi-monitor/fractional/vendor-profile evidence without weakening identity, memory, or fallback boundaries |
| Monitor color presentation is platform-specific | Windows ordinary SDR now has app-side ICC conversion, while Windows Advanced Color/HDR deliberately falls back to legacy sRGB behavior; macOS ColorSync/compositor, X11/colord, and Wayland `color-management-v1` still have different once-only transform boundaries | Productize one bounded platform path at a time; retain explicit unsupported/fallback state and obtain real macOS/Wayland/HDR evidence |
| Raw embedded ICC extraction remains incomplete | A retained normalized `SKColorSpace` is sufficient for supported transforms, but `SKColorSpace.ToProfile()` did not recover equivalent bytes and LUT/unpreserved inputs may need re-extraction from exact encoded source | Add format-specific extraction only where the selected transform engine actually requires it; do not duplicate profiles already represented truthfully |
| Color Picker runtime feel is not cross-platform/fractional-DPI validated | Pure tests cover exact source mapping at 100/125/150/200%, all EXIF orientations, alpha, identity ownership, and render-layer routing; Windows 100% visual smoke covers K, click, ten rows, hide/reopen, mixed-format navigation, fullscreen, Peek/Blink input, temporary Hand, and picker precedence with Markup visible, but real fractional/per-monitor and Linux/macOS panel/cursor/input feel remain unmeasured | Retain the pure geometry and lightweight pointer layer; run representative Windows fractional-DPI plus Linux/macOS manual UI smoke before claiming identical interaction feel |
| HEIF/AVIF support deliberately excludes high precision, HDR, sequences, and collections | R7-C proves one static 8-bit SDR HEVC/AV1 primary, alpha and transforms. `>8` bit, PQ/HLG, sequences, independent-image collections, depth visualization, gain-map reproduction, Live Photo video, and encoding are not product claims | Preserve recoverable rejection/ignored-auxiliary policy until later color/HDR/animation stages can retain fidelity and bounded resources |
| Codec stack beyond JPEG/PNG/static WebP/bounded TIFF/bounded HEIF/AVIF is not selected | RAW, animation, broader variants, and specialized formats vary substantially in correctness, native deployment, precision, and resource cost | Extend the project-owned capability/decode boundaries only when a concrete format stage establishes evidence |
| TIFF support deliberately excludes high precision, pages, and specialist layouts | R7-B proves classic single-image unsigned 8-bit contiguous grayscale/RGB/declared-alpha plus a bounded compression subset. BigTIFF, multipage, >8-bit, float, planar-separated, palette/CMYK/Lab/LogLuv, JPEG-in-TIFF, and huge-image region rendering are not product claims | Preserve recoverable rejection until a dedicated high-bit-depth/color or huge-image stage can retain fidelity and bounded resources; expand individual variants only with deterministic pixels and cross-platform evidence |
| WebP EXIF orientation is not exposed by the current Skia codec boundary | A controlled orientation-6 WebP remains `EncodedOrigin.TopLeft`, so portrait-oriented WebP metadata may display with encoded geometry even though Photo Info can read other EXIF fields | Re-evaluate on Skia upgrades or a future format backend; do not add eager duplicate metadata parsing to normal decode without measured architectural justification |
| Huge-image strategy beyond admission limits is unknown | Full decode may be unsafe while tiled/region support is backend-specific | Start with probe-based limits; investigate tiling later |
| Geometry-independent Windows SDR management adds one full-source device-RGB image | F3 removes every geometry-time raster swap, but adds 4 bytes per encoded pixel at steady state and one equally sized temporary reference surface during source/destination preparation; local 15/24 MP preparation measured about 327/481 ms | Keep ownership to the active source/destination, do not transform the decoded cache, retain source/destination latest-wins, and revisit bounded adjacent preparation or a higher-fidelity GPU LUT only if owner navigation/memory evidence demonstrates a blocker |
| Avalonia/Skia runtime portability is not proven on Linux/macOS | Hosted Windows/Linux/macOS restore-build-test is green for the accepted R7-B checkpoint, including managed TIFF tests, but runtime graphics, WebP/TIFF presentation, DPI, and input remain platform-specific | Perform real Linux/macOS Core Viewer smoke when environments are available; do not equate hosted test execution with manual UI acceptance |
| Automatic memory caps have only Windows local-corpus stress evidence | R2 showed bounded repeated traversal with the R1 formula, but GC allowance, native overhead, and pressure behavior vary by workload/platform | Measure representative large images on additional platforms before turning the constants into stable policy |
| Settings persistence failure has diagnostic-only UX | Load corruption safely falls back and save failure retains in-memory state, but R2 has no unobtrusive secondary error surface | Design a non-modal Settings diagnostic when broader Settings UX is implemented |
| Ambient customization has single-machine visual evidence | The `384 px` prepared size and bounded blur/brightness/saturation ranges are structurally tested, but aesthetic acceptance and slider feel vary with display size, photographs, and destination color behavior | Retain centralized defaults and refine from representative owner use without claiming colorimetric correctness |
| Extreme rapid 24 MP navigation can outrun speculative Ambient readiness | R5-P3 explained the former 5–10-image sustained onset as speculative admission using only unused bytes and fixed the cache-collapse path. Owner review accepts normal human browsing around 3–4 distinct photographs per second. Deliberately browsing roughly 5–6+ full 24 MP photographs per second may still outrun adjacent photo/Ambient readiness and briefly render the matching Black fallback | Retain current photo priority, bounded cache/concurrency, render diagnostics, and strict identity rejection. Treat as a known stress envelope rather than increasing memory or showing stale Ambient; revisit only from future owner evidence |
| Configurable shortcut runtime evidence is Windows-only | Project-owned gestures normalize main-row/numpad cases through Avalonia semantics, but exact key labels and platform layouts can differ | Exercise capture/resolution on Linux and macOS before claiming identical keyboard behavior |
| Peek/Blink runtime evidence is one Windows 100% display | Pure tests cover 100/125/150/200% and local production smoke covers hold, pan, fullscreen, focus loss, and cached comparison, but real fractional-DPI input feel and cold non-cached latency remain unmeasured | Exercise representative fractional/per-monitor environments and record cold/cached/release distributions without creating a universal threshold |
| Photographer-quality Blink feel has a bounded local corpus review | The local adjacent photographs prove functional swapping and state safety, but expression/detail comparison benefits from an owner-supplied near-duplicate burst | Repeat owner review on a representative burst and contain any interaction correction in R4-F1 |
| Presenter overlay isolation runtime evidence is one Windows 100% display | Pure geometry/raster/routing tests cover transform, clipping, erasing, chronology, photo protection, and dirty-layer intent. R5-F3-P1 runtime counters prove photo-draw isolation locally, but the viewport-sized Avalonia bitmap cache and transform-positioned cursor still need real fractional-DPI and Linux/macOS quality/latency validation, including photographic 100% | Exercise real 125/150/200% Windows and Linux/macOS runtimes before claiming identical presenter interaction or cached exact-pixel presentation |
| Long markup histories replay chronologically per frame | The destination-bounded layer avoids permanent full-image allocation and current limits cap retained work, but hundreds of operations cost more than a modest overlay and no representative low-end GPU profile exists yet | Profile real presenter sessions before changing limits or introducing flattening; preserve Undo/Redo and chronology semantics |
| Photo Info metadata coverage varies by camera/producer | R6-A maps common EXIF camera/lens/exposure/date fields through MetadataExtractor and safely collapses missing or malformed data, but maker-specific naming, unusual rationals, PNG textual metadata, and timezone-offset diversity have only bounded fixtures/local smoke | Expand read-only mapping only from representative owner evidence; keep raw backend types contained and never let metadata failure affect decoding |
| Histogram presentation/sampling is an initial bounded policy | R6-B uses linear shared-maximum RGB curves over deterministic samples capped at two million decoded locations. This is responsive and stable for current 10/24 MP evidence, but sparse endpoint spikes, unusual decoded color representations, very large images, and cross-platform native-memory traversal may look or perform differently | Refine display scale/sample policy only from owner evidence; retain whole-image identity, bounded work, alpha correctness, and no monitor-output claim |
| Initial brush is intentionally unsmoothed | The bounded first version records pointer samples as a polyline; fast motion may look angular and no pressure/coalesced-event smoothing is claimed | Refine only from owner presentation use; do not grow into a paint/editor subsystem |
| Physical bracket shortcuts depend on Avalonia OEM key reporting | The project normalizes `OemOpenBrackets`/`OemCloseBrackets` independently of produced text; adapter tests and local Windows EN/RU smoke pass, but other platforms/input methods may report these physical positions differently | Keep the adapter isolated, retain rebinding as the fallback, and validate representative platforms before claiming universal physical-key parity |
| General low-opacity Brush is the current highlighter workflow | Thick translucent Brush provides the required presentation effect without another tool, but owner use has not yet established whether a one-click preset is materially better | Evaluate during owner review and defer any dedicated Highlighter preset to a bounded later stage |
| File-association and thumbnail-provider mechanics are not validated | Registration, sandboxing, packaging, thumbnail APIs, and supported capabilities differ materially across Windows, Linux desktops, and macOS | Validate each platform independently when a concrete packaging or thumbnail milestone begins; do not assume parity |

When evidence resolves a risk, record any durable choice in [`DECISIONS-LOG.md`](DECISIONS-LOG.md), update the owning technical document, and remove or narrow the risk here. Confirmed defects in future code should use the project's eventual issue workflow rather than turning this file into a bug backlog.
